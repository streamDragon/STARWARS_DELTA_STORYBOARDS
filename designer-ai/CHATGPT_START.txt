STARWARS_DELTA DEVORA - SIMPLE V1 CURRENT

CURRENT is the only project truth. CURRENT beats memory. Absence from CURRENT means unavailable. Never infer missing project data.

AUTHORING FLOW
1. Read simple-authoring/AUTHORING_HANDLES.json.
2. Read simple-authoring/AUTHORING_RULES_CURRENT.json.
3. If dialogue is used, read the CURRENT Emotional Dialogue repertoire. Dialogue is closed-world.
4. If an explicit Cutscene projectile is used, use only the closed Cutscene projectile vocabulary exported by the matching CURRENT. Never resolve a gameplay projectile, filename or Catalog lookalike.
5. For visual choices, inspect the Atlas at the exact atlasPage/atlasSlot stored on the selected direct handle.
6. Read simple-authoring/CUTSCENE_SCRIPT_V1_CANONICAL_EXAMPLE.json as the canonical production-shaped example.
7. Author only CUTSCENE_SCRIPT_V1 using simple-authoring/CUTSCENE_SCRIPT_V1.schema.json.
8. Before final JSON, read CURRENT validation. blocksCompilation=true is a real blocker, but never serialize backend-owned fields merely to silence warnings.

NEVER
- Never invent handles or identities.
- Never use raw Catalog asset IDs as Simple V1 handles.
- Never author raw Animation IDs; use animationIntent/performanceIntent.
- Never author V3/V5 bookkeeping fields that are not in the Simple V1 schema.
- Never serialize V4 recipe names; recipes are directing guidance that expands into legal Simple V1 beats/actions.
- Never use Actor/UI/Atlas/name/filename/alias/visual-similarity fallback for dialogue.
- Never use gameplay projectile prefabs or effectHandle/viaHandle as substitutes for Cutscene projectile identity.

MOTION
- Use semantic speeds only: slow, medium, fast, burst.
- Actor Orbit is fixed-center only. The center/target actor must remain stationary during the Orbit interval.
- Pursuit/Escort/Intercept names do not guarantee per-frame target-relative tracking.
- Simple V1 action objects have no per-action timing/order. If one subject needs approach -> pass -> bank -> exit style choreography, split those locomotion phases across adjacent beats. One primary locomotion phase may coexist with compatible fire/impact/reveal events.
- camera.subject is semantic composition intent and is not automatically a physical Transform target.

DIALOGUE
Use only authoringReady characters from CURRENT Emotional Dialogue. actorId, identityHandle and expressionIntent are exact and case-sensitive. Omit expressionIntent for the published defaultExpression. Unsupported expressions block; there is no Neutral fallback. DialoguePortrait participants do not become WorldActors merely to satisfy camera targeting.

CUTSCENE PROJECTILES
- The Cutscene projectile system is a closed visual-only capability, separate from gameplay shooting and Netcode.
- For type=fire, projectile identity belongs only in projectileId.
- Legal projectileId values are the exact values exported by the matching CURRENT Cutscene projectile capability. The prepared V1 repertoire is CS_PROJECTILE_LASER, CS_PROJECTILE_AXE and CS_PROJECTILE_ROCKET once that capability is present in matching CURRENT.
- Explicit unsupported projectileId is a blocker: CUTSCENE_PROJECTILE_NOT_AUTHORING_READY. No fuzzy match, filename match, gameplay fallback or effect substitution.
- projectileId is optional for backward compatibility. Omission preserves the existing legacy fire behavior.
- count is the existing fire quantity field. Launcher/muzzle position, muzzle rotation, projectile physics and backend interval defaults remain Unity-owned unless CURRENT explicitly exposes otherwise.

REFERENCE
- AUTHORING_HANDLES.json is the direct Simple V1 selection surface. Raw Animation identities remain backend compatibility data and are intentionally excluded.
- Direct visual handles contain atlasPage/atlasSlot; FULL_VISUAL_INDEX is not required for normal authoring.
- simple-authoring/CUTSCENE_SCRIPT_V1_CANONICAL_EXAMPLE.json is the one canonical example.
- V3 and V5 remain backend layers and are not authoring formats.
