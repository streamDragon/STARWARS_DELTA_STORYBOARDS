FORMAT LOCK
The only legal root header is:
{
  "schema": "STARWARS_DELTA_CUTSCENE_SCRIPT",
  "schemaVersion": 1
}

Use the schema literally. Unknown fields and remembered aliases are forbidden.

CURRENT FINGERPRINTS ARE NOT MOVIE FIELDS
Do not serialize catalogRevision, contractRevision, schemaHash, snapshotContentHash, authoringRuleRegistryRevision, publishTransactionId, requiredCurrent or runtime GUIDs into normal CUTSCENE_SCRIPT_V1 unless a future matching schema explicitly defines them.

IDENTITY
- cast[].id is narrative identity used by actions/dialogue/continuity.
- cast[].identityHandle is the exact CURRENT canonical/preferred route=Actor authoring identity.
- visible[].handle selects the visible representation.
- actions[].subject references cast[].id.
- animationIntent/performanceIntent are semantic requests. Never author raw AnimationClip IDs.
- Sprite frames, portraits, textures, animation frames and raw Catalog IDs do not become Actor identity because they look related.
- If CURRENT does not expose a legal Actor handle, the Actor is unavailable for direct authoring. Do not infer one.

CATALOG / VISUAL EVIDENCE
- AUTHORING_HANDLES.json is the normal direct selection surface.
- Raw Catalog IDs are engineering/runtime evidence, not normal authoring vocabulary.
- Destination route/capability beats filename, folder, display name and visual resemblance.
- Use route=Actor for world identity, Layer for scenery, Effect for VFX, Ui for UI/dialogue presentation and Audio for sound.
- Real pixel evidence decides appearance. Metadata is search evidence only.
- Do not directly author source sheets, assembly parts, unsafe/pending-review assets or technical helper content when CURRENT excludes them.

STORY AND EVIDENCE
Every production beat needs a clear audience-observable purpose. Dialogue or a title saying an event happened does not implement the visible event.

VISIBLE EFFECTS / PARTICLES
- A legal route=Effect item in visible[] is already an audience-visible obligation.
- Do not add meaningless reveal/activate actions merely to wake up an Effect.
- repeated identical Effect handles remain distinct authored instances.
- Effect timing uses visible[].startOffsetSeconds / visible[].durationSeconds when present.
- overlaps are legal.
- projectiles/impacts do not implicitly satisfy unrelated visible Effects.
- Particle/prefab lifecycle is Unity-owned; authoring expresses the visible obligation, not the low-level particle component wiring.

ACTOR ANIMATION AND MOTION
- Animation and movement are separate and may run simultaneously.
- compatible real animation is requested through semantic animationIntent/performanceIntent.
- actor motion uses only schema-legal motionIntent/path fields.
- exact path geometry uses the schema's pathShape/pathPoints fields when needed.
- semantic speed is only slow, medium, fast or burst.
- Actor Orbit remains fixed-center while the matching runtime capability requires it.
- do not assume pursuit/escort/intercept means per-frame moving-target tracking unless CURRENT/runtime explicitly supports it.

ACTION TIMING
- actions[].startOffset is optional seconds from beat start.
- actions[].duration is optional action duration.
- explicit intervals must remain legal and inside the owning beat.
- actions[] array order is never hidden sequencing.
- use explicit intervals for staggering/concurrency.
- use adjacent beats for distinct semantic movement phases unless one continuous precise path intentionally represents the whole movement.

CAMERA
Camera authoring is semantic directing intent.
- framing/movement/subject/direction/intensity use only matching schema values.
- camera.subject is semantic composition intent and is not automatically a physical Transform target.
- Hold may preserve semantic composition without a physical target.
- Follow/Track may bind an active legal WorldActor when runtime support exists.
- camera Orbit is a 2D/2.5D composition concept, not invented unseen 3D geometry.
- Push/Pull mean continuous within-shot framing change, not merely a cut to another static lens size.
- Drift/Orbit/Shake/ImpactShake must be visibly meaningful when Unity executes them; technical non-zero movement that is imperceptible is not exact success.
- locked portrait dialogue defaults to stable legal coverage; do not mix unsupported world-camera motion into a locked dialogue beat.

DIALOGUE
Dialogue is closed-world.
- speaker/listener must be exact authoringReady actorId values from EMOTIONAL_DIALOGUE_CURRENT and match cast[].id.
- dialogue cast identityHandle must equal the published identityHandle for that actorId.
- expressionIntent is exact and case-sensitive; omit it to request the published default.
- do not invent identity, expression or presentation values from generic Catalog evidence.

AUDIO
- each cue uses kind + exact CURRENT route=Audio handle.
- repeated uses remain separate authored occurrences.
- visual Effects and projectiles do not automatically supply sound.
- generated simple_audio_* identities are backend-only.

CUTSCENE PROJECTILES / MISSILES
- every type=fire action requires a schema-legal projectileId.
- projectileId is closed-world and comes from the matching schema.
- count is a real authored quantity.
- projectile identity is never an Effect handle, filename, gameplay prefab name or fuzzy match.
- target/anchor intent must remain exact when authored.
- launcher, muzzle transform, collider wiring, travel mechanics and Timeline receiver implementation remain Unity-owned.

CONCURRENCY
The system must support legal simultaneous operations rather than serializing them merely to avoid conflicts. Examples include:
- actor animation + actor movement;
- actor animation + camera movement;
- moving shooter + fire;
- two-way fire + camera shake;
- camera framing change + a separate compatible perspective property.
One runtime property/capability still has one effective owner for the same interval.

ACCEPTED FIXTURE / BACKEND REPAIR DISCIPLINE
Once a legal CUTSCENE_SCRIPT_V1 fixture passes authoring integrity, downstream BACKEND/ENGINE failures are repaired against that same authored fixture.
- do not rewrite legal beats/timing/handles/camera intent/animation intent/projectile counts/targets merely to hide runtime failure;
- fixture names, beat IDs, actor IDs and timestamps never become production special cases;
- compile-only success is not movie-quality proof;
- runtime PASS requires actual Unity execution of the final saved/reopened Editable Preview.

FAIL-SOFT DISCIPLINE
- Author strict, Studio tolerant.
- deterministic safe repair may continue with YELLOW/ORANGE diagnostics.
- never report fallback/degradation as exact success.
- preserve the last valid Editable Preview when a new candidate fails where possible.
- legal source intent lost after lowering/materialization is BACKEND/ENGINE-owned, not a reason to corrupt source authoring.
