THE CORRECTION

Correct reference

The cutscene camera is the reference frame.

Choose the shot camera and framing first. Then decide how much of that camera frame each visible sprite should occupy.

Camera framing first
Screen occupancy second
Real sprite bounds third
Unity transform scale last

Do not use

Gameplay World Bounds are not the sizing reference for a separate cutscene screen.

Those bounds describe the gameplay stage. They are irrelevant to cutscene sprite sizing unless a particular cutscene explicitly takes place inside that gameplay world.

WRONG: Gameplay width -> guess ship size -> guess scale RIGHT: Cutscene camera -> desired screen occupancy -> real sprite bounds -> scale

WHY THIS MATTERS

Same asset, different shot

A ship may be 12% of frame width in a wide establishing shot, 24% in a medium shot, and 42% in a close threat reveal. The sprite itself did not become a different physical object. The camera/framing relationship changed.

Same camera, different assets

A person, fighter and capital ship should not be assigned the same raw transform scale. Unity must use each resolved asset's natural Renderer/Sprite bounds to reach the requested screen occupancy while preserving aspect ratio.

CORE RULE: CAMERA DEFINES THE FRAME. SCREEN FRACTION DEFINES THE VISUAL SIZE. REAL SPRITE BOUNDS DEFINE THE SCALE.

FROM CAMERA TO SCALE

Deterministic conversion, not adjective guessing

STEP 1 - RESOLVE THE ACTIVE CUTSCENE CAMERA

The system resolves the actual camera for this shot. For an orthographic camera:

visibleHeight = orthographicSize * 2 visibleWidth = visibleHeight * cameraAspect

1Camera first

Camera position, orthographic size, aspect ratio and shot framing establish the visible 2D rectangle.

No gameplay rectangle is required. A cutscene-only scene can be authored entirely from its own camera frame.

STEP 2 - AUTHOR WHAT THE AUDIENCE SHOULD SEE
ship.screenX = 0.22 ship.screenY = 0.55 ship.screenWidthFraction = 0.18 character.screenHeightFraction = 0.25 effect.screenWidthFraction = 0.05

2Screen occupancy

ChatGPT / Debora chooses normalized frame position and how much of the current shot the object should occupy.

Use width fraction when width is the important visual constraint, height fraction when height is the important constraint. Preserve the asset's natural aspect ratio unless the authoring contract explicitly says otherwise.

STEP 3 - USE THE OBJECTIVE SIZE OF THE RESOLVED SPRITE

3Measure real asset

Unity measures the actual natural Renderer/Sprite bounds of the resolved CURRENT asset.

naturalWidth = renderer.bounds.size.x naturalHeight = renderer.bounds.size.y

This is the objective visual size of that sprite before the cinematic scale multiplier.

4Calculate scale

desiredWorldWidth = cameraVisibleWidth * screenWidthFraction
scale = desiredWorldWidth / naturalSpriteWidth

Equivalent height-based calculation is used for screenHeightFraction. The final transform keeps the natural aspect ratio.

NO RAW "LARGE / SMALL" SCALE TABLE. THE SCALE IS DERIVED FROM CAMERA + SCREEN OCCUPANCY + REAL SPRITE BOUNDS.

GOLDEN

Clear cinematic intent. Unity can derive deterministic world scale from the actual resolved assets.

PER-SHOT RECOMPUTE

Camera changes?

Recompute visible camera width/height and therefore the world scale needed to preserve the requested screen fraction.

Asset changes?

Measure the new asset's natural bounds and compute a new scale. Never reuse a transform scale merely because the semantic role is similar.
