Create a canonical JSON wave plan for the simplified Reverse Wave Authoring Unity tool.
Apply always targets the currently active Unity scene.

OUTPUT
- Return one valid JSON object with a "waves" array. No comments or trailing commas.
- Use only the canonical fields documented below. Do not add compatibility aliases.
- Never invent asset names, paths, or scene markers. Copy them exactly from the live catalogs below.
- Author spawnType as "Auto" for every new wave. Do not choose Boss/NavMesh/Spline/Bouncy/SpriteShapeTrack as spawn modes.
- Choose enemyPrefabName from the live spawnable prefab catalog. Runtime movement is inferred from the selected prefab's components.
- Every wave has an effective spawn point, including Spline waves. For an existing point, use spawnPoint. For a NEW point, use exactly one relative relation: road-fraction or source-relative. If placement is omitted, WavesManager uses the canonical generic spawn point.

CANONICAL PLAN FIELDS
- planTitle: string (optional)
- waves: array (required)

CANONICAL WAVE FIELDS
- id: string
- displayName: string
- stageIndex: integer, required, zero or greater
- kmStart: positive finite number, required and unique within its stage
- count: positive integer
- healthOfEnemy: positive integer wave health override; for bosses it applies to every BossPartHandler; omitted uses the existing WaveDefinition default of 5
- spawn: { "intervalSeconds": positive number }
- speed: number for ordinary enemies and the selected Humanity movement mode
- passengerCount: Humanity wave-owned passenger count; prefab value is fallback only
- spawnType: always "Auto" for new JSON. It is not a movement selector.
- spawnPoint: optional exact active-scene hierarchy path for an already-existing point.
- hasSpawnRoadNormalizedArcLength: optional boolean. Emit true only when requesting a NEW point at an arbitrary fraction along trackRoadId.
- spawnRoadNormalizedArcLength: number from 0 to 1, measured by cumulative sampled Unity-world-space arc length along the exact road. 0=start. On an open road 1=end; on a closed road 1=one complete loop and resolves back to the start. spawnRelativeWorldOffset is added afterward in Unity world units.
- spawnRelativeSourceId: optional stable source ID from the spatial snapshot for a NEW source-relative point. Do not combine it with hasSpawnRoadNormalizedArcLength=true.
- spawnRelativeWorldOffset: optional { "x": number, "y": number, "z": number } in Unity world units, applied after resolving either the road fraction or source point.
- movementMode: retired compatibility field; do not author it in new JSON
- trackBehavior: optional SpriteShapeTrackBehavior value: Forward, PingPong, ChasePlayer, or ReverseOnBlock
- trackInitialDirection: -1 or 1
- trackRoadId: optional exact MY_SpriteShapeRoad ID; empty means nearest eligible road
- trackMaxAttachDistance: positive world-unit attach distance; default 12
- trackStartPointIndex: zero or greater
- trackEndPointIndex: -1 for natural end, otherwise greater than trackStartPointIndex
- trackChaseDeadZone: non-negative world distance used only by ChasePlayer
- trackPingPongDistance: optional non-negative patrol distance in world units; 0 disables the distance limit
- trackPingPongDuration: optional non-negative patrol time in seconds; default 6.0 for PingPong when no patrol distance is authored
- trackBlockCheckDistance: positive look-ahead distance used by Forward and ReverseOnBlock; default 0.35
- enemyPrefabName: exact prefab path from the current catalog (bare names remain accepted only when unique in that catalog)
- prefabPath: optional compatibility alias; when present it is preferred as the exact prefab reference
- mlbPrefabName: optional exact MLB or MLL prefab name; empty means no Wave override
- splineName: exact reusable spline SHAPE prefab path. When used with spawnPoint, the first knot is translated to the spawn point (including a scene tower exit); one spline works at multiple heights. If omitted, the level default SP_DEFAULT_SPLINE is used. A Boss remains Boss even with a spline route.
- navMeshEndPoint: optional movement destination for a prefab that runtime classifies as NavMesh. Initial placement still comes from spawnPoint.
- navMeshPositionSpace: "World" (default) or "GameSceneLayerRelative"
- navMeshGameSceneLayer: existing scene hierarchy path to the moving Game Scene Layer; required only when navMeshPositionSpace is GameSceneLayerRelative. NAV start/end markers must be children of this layer.
- navMeshLayer: Unity GameObject layer for the spawned NAV enemy; default 0. Only change this when the user explicitly asks for a different layer.
- navMeshRotateNoseToMovement: whether the NAV ship visually turns its nose toward its actual movement direction; default true. Emit false only when the user explicitly wants fixed visual orientation.
- navMeshInterceptLeadSeconds: InterceptPlayer look-ahead time in seconds; default 0.65, non-negative. Emit it only when a different lead is intentionally requested.
- navMeshGuardRadius: GuardArea radius in world units; default 2.0, minimum 0.5
- chaseStartPoint/startPosition/trackStartPoint/navMeshStartPoint: legacy import aliases only. New JSON uses spawnPoint.
- navMeshBehaviour: optional NavMesh behaviour: FollowPlayer, InterceptPlayer, GuardArea, FollowEnemy, or GoToDestination
- chase: optional object with acceleration, stoppingDistance, reacquireInterval, faceMovementDirection, facingAngleOffset, rotationSpeed, useRigidbody2DWhenPossible, moveOnlyOnServerWhenNetcodeIsListening, allowDirectSceneMovementWithoutNetcode
- waveColor: Unity color string/value supported by JsonUtility
- spawnTeleportType: "None", "Random", "RespawnCyan", "WarpBlue", "ShockwavePurple", or "DissolveWhite"; omitted defaults to Random for normal enemies and None for Humanity vehicles
- spawnTeleportDuration: positive seconds; default 3.0. "None" means no teleport.
- powerUpPrefabName: optional exact valid pickup name

HUMAN-FACING MAP GUIDANCE
- Before returning JSON, explain the drawing to the user in plain language.
- Briefly describe the important visible geometry: major roads, markers, large objects/openings, and any approximations or warnings that affect placement.
- Explain the practical placement choices the drawing enables, for example: choose an existing marker; request a new percentage along a specific robot road; or place relative to a stable source object with a world-space offset.
- When proposing locations, name the exact road/source IDs and describe where they appear on the drawing (for example "about one third along the upper road, just before the large asteroid").
- Explain what you recommend placing there and why it fits the user's request. Distinguish a recommendation from a fact read from the map.
- If several placements are reasonable, present the meaningful alternatives rather than silently choosing one.
- Never claim collision clearance, walkability, or obstacle status from visual geometry alone. Geometry approximations are for planning/communication unless the exported data explicitly says otherwise.
- After the explanation, return the importable JSON proposal. The user should not have to translate pixels or map positions into Unity coordinates manually.

RESOLUTION AND APPLY CONTRACT
- Enemy, robot, boss, Humanity, MLB/MLL, pickup, and spline references resolve only to existing project-owned assets in the live catalogs below.
- A full Assets/... prefab path is preferred. A bare name is accepted only when it identifies exactly one spawnable prefab in the current catalog; there is no out-of-catalog name fallback.
- Spline waves require an existing spline prefab. JSON point-to-spline generation does not exist.
- Existing positional placement may use spawnPoint to reference a valid live point.
- A NEW arbitrary placement is requested through exactly one relation: (a) hasSpawnRoadNormalizedArcLength=true + exact trackRoadId + spawnRoadNormalizedArcLength, or (b) spawnRelativeSourceId. spawnRelativeWorldOffset may refine either relation.
- Import/Validate materializes requested relations as managed points under Layer0/מיקומים יחסיים/GENERATED_WAVE_ANCHORS. Apply saves them with the existing Wave plan and WavesManager references them through the normal spawnPoint/Transform contract.
- COPY AI remains read-only and never creates those points.
- If no explicit or relative placement is authored, Preview/Validate/Apply resolve the canonical generic WavesManager spawn point.
- A leaf marker is used directly, even when its authoring GameObject is inactive. A group marker uses one of its active direct children.
- All new Spline waves move the chosen spline shape relative to spawnPoint, or to SPAWN_BOTTOM_FAR_RIGHT when no point is specified. Never invent four copies of a spline for four heights; choose the same splineName with different spawnPoint values.
- COPY AI must emit navMeshPositionSpace for every NavMesh wave, navMeshLayer=0 unless the user explicitly requests another Unity layer, navMeshRotateNoseToMovement=true unless the user explicitly requests fixed visual orientation, and navMeshGuardRadius=2 unless a different GuardArea radius is intentionally requested. Emit navMeshGameSceneLayer whenever navMeshPositionSpace is GameSceneLayerRelative. For GameSceneLayerRelative + GoToDestination, also emit an explicit navMeshEndPoint that is a child of that same navMeshGameSceneLayer; do not rely on the world-space canonical NAV end.
- Canonical spawn position for EVERY wave, including Spline, is 'SPAWN_BOTTOM_FAR_RIGHT' inside Gameplay_PlayerBounds/04_WAVE_SPAWN_GRID. Spline also selects a route SHAPE, default 'SP_DEFAULT_SPLINE', then translates its first knot to the chosen spawn position.
- Explicit authored location always overrides the matching default. Preview shows authored/effective/source; Validate warns when a default is used and errors only when the effective placement cannot resolve.
- The prefab catalog is prefab-derived. Use only spawnable=true entries; supported movement metadata is read-only runtime context, not an authoring choice.
- Entries under NON-SPAWNABLE ROBOT TEMPLATES are authoring bases and must never appear in waves.
- Apply offers Replace All (erase all stages/waves), Merge Stages (replace incoming stage indices while preserving other stages), and Append Stage (add one new stage after existing stages); it marks the scene dirty and saves only after validation.
- Legacy spawn-type names are accepted on import only and normalize to Auto. New authoring writes Auto.
- speed, SpriteShapeTrack settings, NAV settings and spline routes remain movement data when the selected prefab uses them.
- Do not author autonomousSpawnPointRoot directly; use spawnPoint for positional placement.
- `mlbPrefabName` is a WaveDefinition.MissileLauncher override and is kept separate from `enemyPrefabName`.
- A valid Wave weapon override wins over a prefab-owned route at runtime. Without an override, a single complete prefab-owned route remains authoritative; multiple owners or incomplete Direct Weapon wiring are invalid.

POWER-UPS
- Normal applied waves receive one valid Power-Up in WaveDefinition.powerUp when no explicit exception is authored.
- If powerUpPrefabName is present, that exact valid prefab wins.
- If omitted or empty, Apply selects from the valid pickup catalog using one System.Random seeded with 1337. Selections vary across waves and repeated Apply results are stable.
- Humanity vehicles default to no Power-Up because their runtime contract does not require one; an explicit valid powerUpPrefabName remains supported.
- A valid pickup is under Assets/_Game/MY_Prefabs/PowerUpPrefab, has MPowerUpBrain, is not templateOnly, and HasConfiguredEffect() is true.
- Eligibility is the same predicate used by Reverse Wave Authoring; vendor visual Pickup assets outside this gameplay folder are excluded.
- Drop control: WavesManager.GivePowerUpAtPosition spawns WaveDefinition.powerUp at the last enemy's position after the wave-clear condition. Humanity defaults to no Power-Up unless explicitly authored.
- Random selection is a deterministic authoring fallback (System.Random seed 1337), not a runtime probability field.
- An invalid explicit pickup or an empty valid pool blocks Apply for normal waves. Humanity without an explicit pickup remains valid.

RUNTIME-OWNED FIELDS NOT IN CANONICAL JSON
- Do not invent JSON for pointsForKillingMe, diesOnFall, explodeOnFallDeath, useTimer, expiryTime, towerData, bossInfo, or low-level gravity/surface tuning. The current Reverse Apply path intentionally leaves these runtime/designer-owned defaults intact.
- Do not author autonomousSpawnPointRoot directly; it is derived from spawnPoint or the canonical 04_WAVE_SPAWN_GRID default.
- Do not use spline point arrays or generate a spline from JSON. Only an exact current spline prefab/path is consumed.

Humanity rules:
- A prefab is Humanity only when it contains MY_EvacuationVehicle.
- Derive People and Vehicle Type from MY_EvacuationVehicle.
- Author passengerCount and speed on the normal WavesManager wave entry; spawnType remains Auto and the prefab selects Spline or SpriteShapeTrack movement.
- MY_HumanityVehicleMovement is the active bridge/router selecting SplineAnimate or MY_SpriteShapeTrackMotor2D; it is not a third movement system.
- The normal Humanity wave contributes KM, count/timing, speed, and initial placement. spawnType remains Auto. Track and spline fields are movement data inferred from the prefab.
- Humanity SpriteShapeTrack follows the same generated SpriteShape road used by track robots; there is no second physics-road, marker road, or layer-based walking contract.
- Spline success is resolved from the existing SplineAnimate completion path. SpriteShapeTrack uses its normal vehicle arrival/outcome contract.
- A Spline Humanity wave needs a valid splineRoute. Positional Humanity placement uses spawnPoint or the canonical generic 04_WAVE_SPAWN_GRID default.
- A destroyed vehicle loses its carried humanity; a vehicle reaching its destination saves it. MY_HumanityState is the canonical state source: LivingHumanity and SavedHumanity.
- Do not describe pickup, boarding, transfer, registry, or dedicated Humanity-spawner concepts. Do not add `isHumanity`; MY_EvacuationVehicle remains the runtime source of truth.

Humanity SpriteShapeTrack COPY AI rules:
- Identify Humanity using MY_EvacuationVehicle.
- Keep spawnType=Auto. Do not author movementMode.
- Use spawnPoint when an explicit initial position is desired.
- Use trackRoadId when a specific authored road is required; otherwise runtime may bind the nearest eligible MY_SpriteShapeRoad within trackMaxAttachDistance.
- Provide Humanity speed plus trackBehavior, trackInitialDirection, trackStartPointIndex, trackEndPointIndex, trackChaseDeadZone, trackPingPongDistance, trackPingPongDuration and trackBlockCheckDistance only when they differ from the normal defaults.

Humanity Spline COPY AI rules:
- Keep spawnType=Auto and provide passengerCount plus the exact existing spline route when the Humanity prefab is configured for Spline. Do not author movementMode.
