# Art delivery and catalog intake

Treat delivery as a completed transfer only after the existing Unity and catalog routes verify it. Operate on the delivered asset paths once at the delivery boundary; use the existing incremental scanner and its completion event. Keep continuous background scans and a second catalog out of this workflow.

## Required delivery data

Retain the pack root, exact files/sub-assets, source hashes, intended static/animated roles, pixel size, alpha, PPU and pivots. For every animation retain ordered frame paths, FPS, loop/one-shot intent, local binding path and event/trigger intent. Inspect actual pixels and importers. A manifest's recommended values are input; Unity's resolved objects/settings are evidence. PPU=100 is an example from a pack, not a global rule.

## Intake sequence

1. Verify the delivered files against the manifest; preserve existing GUIDs and reviewed metadata. Report missing files, hash differences and ambiguous classification precisely.
2. Use supported Unity import/configuration operations and verify Sprite sub-assets, importer values, dimensions, pivots and transparency. Keep preview/contact-sheet images distinct from production sprites.
3. Materialize declared frame sequences as ordinary AnimationClip assets through existing Unity tools/APIs. Use the specified order, FPS and loop intent; verify SpriteRenderer bindings and frame duration. Start sprite object-reference curves with one key per source frame at index/FPS and verify the actual clip length against frameCount/FPS. Check endpoint behavior before adding a terminal key; a duplicate tail may add an extra frame. Inspect existing controllers and gameplay events before assigning clips. Keep destruction/open/close events separate from ambient loops.
4. Use the existing UnifiedAssetCatalogScanner.ScanPaths(exactDeliveredAndCreatedPaths, false) from the authorized delivery operation after Unity import completes. This is the bounded automatic intake step. If a scan/import/compile/play operation is already running, report the real state and defer the conflicting operation; do not start a concurrent scanner.
5. Wait for that scanner's terminal outcome. Its ScanCompleted event refreshes the Level Builder projection. Rebuild the projection from the current catalog when necessary; a scan-start acknowledgement or an immediate stale projection is not registration.
6. Verify exact GUID/local-file identities, role capabilities and current catalog revision. Static Decoration sprites may be Layer0 visual content without geometry/background capabilities. Preserve collision/gameplay authority in existing prefabs.
7. Keep verified or explicitly declared animation frames resolvable in the authoritative catalog while excluding them from independent placement choices. Expose the actual clips and compatible visual assembly through supported routes. Numbered filenames alone do not prove frame membership; require explicit delivery metadata or real clip references.
8. Produce a receipt and obtain a fresh Copy for Chat package before authoring JSON. Register assets through the shared mechanism, using capabilities/evidence rather than hard-coded level names or pack paths.

## Intake receipt

| Slot | Required content |
| --- | --- |
| Delivery | Root, manifest/hash, expected and actual file/sub-asset counts |
| Unity import | Resolved Sprite objects and importer facts; missing/invalid entries |
| Static choices | Exact asset IDs, permitted roles, dimensions, pivots and revision |
| Animation choices | Clip IDs/paths, ordered frame count, FPS, loop intent, binding and compatible controller/assembly |
| Excluded/pending | Every source frame/technical image/unclassified asset, reason and next action |
| Scene integration | Actual placements/bindings tested, or explicitly pending |
| Acceptance | Matching QA run/captures and behavior results, or explicitly not performed |

Report these distinct states: source delivered; Unity import verified; catalog registration verified; animation assets verified; scene integration verified; QA accepted. Counts of PNGs and .meta files establish the first state only. A static first frame may be a marked placeholder with an exact replacement ledger; it does not count as a working animation.

For ambiguous semantics, retain the source asset and issue a focused review/task instead of assigning gameplay behavior from a name. For a missing tool capability, include a reproduction and acceptance test. Generalize the shared eligibility rule when appropriate; avoid solving each new level by adding another path exception.
